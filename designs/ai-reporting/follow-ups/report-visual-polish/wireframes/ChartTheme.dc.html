The merge rule decides the split. ECharts applies a registered theme under the option — anything the option pins wins. Flint's compiled option pins the stock palette (color: ["#5470c6", …]) and a per-series itemStyle.color, so the palette can only land in the server compile pass; the theme object carries what flint leaves unset.
Compiled into the option server · buildFlintOption post-pass
  • color — replace flint's pinned defaults with the module palette #0b7a5c · #8c5bb0 · #b0722a · #3f6fae
  • series[].itemStyle.color — delete, so the palette assigns by series order (color follows the entity)
  • bars: itemStyle.borderRadius: [4, 4, 0, 0] — rounded data-ends, square baseline
  • lines: lineStyle.width: 2, end-point symbol with a surface ring, areaStyle gradient on single-series lines
  • pie: itemStyle: { borderRadius: 4, borderWidth: 2, borderColor: surface } — the 2px slice gaps
Theme object client · EChart properties.theme
  • textStyle.fontFamily — the app's sans for axis labels, legend and tooltip text
  • categoryAxis / valueAxis — axis lines in the rule token, split lines one step quieter, muted label ink
  • legend.textStyle and tooltip — surface, hairline border, ink tokens
  • backgroundColor: transparent — the section card owns the surface
  • one theme object, shared by every EChart the module renders: report sections, chat cards, the expand modal
Wiring the EChart block registers a theme object per block — verified in blocks-echarts 5.5.1 
- id: sections.$.chart
  type: EChart
  properties:
    height: { _state: sections.$.height }
    option: { _state: sections.$.option }   # palette + mark styling compiled server-side
    theme:
      _ref: defaults/chart_theme.yaml       # typography + axis chrome, one file for every chart
