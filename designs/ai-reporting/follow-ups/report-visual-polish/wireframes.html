The data is right. The page is unfinished.

A saved report today is nine bare blocks on a flat plane: no containers, no comparison, tables that either clip or run half-empty, and the stock ECharts palette — which fails four of five accessibility checks on the surface it actually renders on. None of that is a chart problem. It is layout and chrome, and the module owns almost all of it.

  1. 1Four filters, four near-identical grey paragraphs. filterControlBlock puts every other bound section in the label's extra. Sound for one filter; at four × six sections it costs ~250px — more than any chart on the page.
  2. 2No units, no comparison, no shared baseline. 25.0 is a percentage. The four Statistic blocks self-size, so the tallest value pushes its own label ~16px above its neighbours' and the row reads as four fragments.
  3. 3The legend owns a dead gutter. Flint reserves grid.right for its vertical legend — measured 79–163px, sized to the longest series name. At full width that is fine; the problem is it is the only option today.
  4. 4A 4-slice pie in 1100 × 400px. Every chart and table is span 24. Nine sections × full width is 7810px of scroll for data that fits in a third of it.
  5. 5Two columns in an 1100px table — ~600px of blank white, because table width is not derived from column count.
  6. 6…and a six-column table clipped mid-header. Same rule, opposite failure. One flex: 1 on defaultColDef fixes both.
  7. 7Rotation ignores available width. Flint's rule (read off its source): rotate: 0 only at ≤ 4 categories and ≤ 8-char labels, else 90 — width is never consulted, so three ten-character labels with ~340px of room each get rotate: 90, byte-identical at 1100px and 520px canvas. It also inflates grid.bottom 61→91 and then collides with the axis title nameGap: 25 puts beneath it.
  8. 8Downloads stranded at the bottom, 4 + 1 ragged, under no heading — a second download idiom in a report that already puts ⤓ in each section's head row.

  1. 1The header is already right — title, description, provenance, ★, ⋯, Continue in chat. Nothing in this design touches it. The long title is the agent's, not the renderer's.
  2. 2One scope line, not four. When every filter in a run drives the same sections, say it once. When they differ, keep the note only on the controls that actually differ — plus a Reset, which 4 of 7 client reports carry and the module has no equivalent of.
  3. 3Tiles are cards, so the row is a row. Equal height comes from the card, not from Statistic's self-sizing. The unit comes from the contract format the section already carries.
  4. 4Narrow charts pair 2-up at span 12. "Narrow" is decided from data the compiler already holds: no temporal axis, ≤ 8 categories, ≤ 4 series. A pie is never wide.
  5. 5Tables never pair — always full width. A half-width AgGrid is a horizontal-scroll trap; instead flex: 1 spends the row on the columns, so no blank white and no clipping.
  6. 6A trailing unpaired narrow section is promoted to full width. A half-width card with twelve empty columns beside it reads as a rendering fault, which is worse than a slightly over-wide chart.
  7. 7Legend orientation follows available width. At span 12, horizontal above the plot. At span 24, Flint's vertical right legend is correct — the gutter now buys something.
  8. 8A download run becomes one titled card. The ⤓-in-the-head-row stays the only per-section export idiom a reader has to learn.

Plate 3 section list → layout the whole mechanism

Layout is a function, not a choice

The agent emits an ordered list of typed sections and contributes no layout — that stays true. There is no archetype field, no layout: key, no density toggle. A run is a maximal sequence of adjacent same-type sections; compileReport already walks sections in order, so runs are the only new concept. Spans are on the existing 24-column grid.

Section run Compiles to Grid
kpi × 4 One tile row — spans from filterSpans(n), so every wrap line is exactly full. Reused, not reinvented: it already solves balanced rows and whole-number columns. 6 · 6 · 6 · 6
kpi × 5 Balanced 3 + 2, never greedy 3 + 1 + ragged — a ragged trailing line lets the next section flow into the leftover columns. 8·8·8 / 12·12
filter × n Unchanged grouping (≤ 3 per row) plus a Reset and one shared scope line. 24 / n
chart — needs width Full-width card. Needs width = temporal x-axis, or > 8 categories, or > 4 series. 24
chart — narrow Half-width card, paired 2-up with the next consecutive narrow chart. A pie is never wide. 12 + 12
table Always a full-width card, flex: 1 columns — tables never pair; a half-width AgGrid is a horizontal-scroll trap. 24
trailing unpaired Promoted to full width rather than left beside a hole. 12 → 24
download × n One "Downloads" card; buttons inside at filterSpans(n). 24
markdown Full width, no card — prose narrates between cards rather than sitting in one. 24
  1. 1Why not archetypes. Each adds a decision the agent or the saver has to make correctly, and three layouts is three code paths owed forever for a benefit nobody has asked for. The derivation is mechanical, so it cannot drift per report.
  2. 2Why the head row stays outside the card. 6 of 7 client reports put the heading above the card. It also leaves sectionHeading / sectionDownload and their span-20/span-4 arithmetic untouched.
  3. 3The risky line. Card and Box must join report.yaml's Dynamic types.blocks allowlist, where one missed type blanks the whole report to the fallback slot rather than one section.

Plate 5 buildFlintOption — post-assembly rewrite new

The palette is computable, so it was computed

buildFlintOption already post-processes Flint's output — it strips private keys, overrides barWidth, moves the legend and pins pie geometry. The rewrite point exists; nothing new has to be invented.

Stock ECharts — what Flint ships fails
  • FAILLightness band — #91cc75 0.784, #fac858 0.857
  • FAILChroma floor — #73c0de reads grey
  • FAILCVD separation — worst adjacent ΔE 4.0 (protan)
  • FAILNormal-vision floor — ΔE 13.9, below the 15 floor
  • WARNContrast — 4 of 8 below 3:1

The normal-vision ΔE is the damning one: slots 2 and 3 are hard to tell apart with full colour vision, before CVD is considered.

Reference categorical palette all checks pass
  • PASSLightness band — all 8 in band
  • PASSChroma floor — all 8 ≥ 0.1
  • PASSCVD separation — worst adjacent ΔE 9.1
  • PASSNormal-vision floor — worst adjacent ΔE 19.6
  • WARNContrast — 3 below 3:1, relief discharged

Validated against this repo's real surfaces — #ffffff light, #141414 dark — not the skill's defaults. Dark passes contrast too. The light WARN obligates visible labels or a table view; a compiled report has both (a legend on every multi-series chart, a ⤓ on every section).

  1. 1Two writes, not one. Flint declares the palette as option.color and as a concrete hex on each series[i].itemStyle.color — and the per-series value wins on bar and line. Setting option.color alone is a silent no-op there. Pie is the exception: no per-slice colour, so option.color drives it.
  2. 2Assert it. A test should check no stock hex survives anywhere in the option tree, on all three chart kinds — this is the kind of half-fix that looks right in a diff and is wrong on screen.
  3. 3Colour identity is report-scoped. Today hues come from series index within one chart, so Done is red in one section and green two sections later. Assign slots from the union of series names across the whole report, first-appearance order — "colour follows the entity, never its rank". Past 8 names, fold the tail to Other; never cycle.
  4. 4Rotation gets the width Flint ignores. Compute available px per category from the plot width the span actually gives, and step 0 → 45 → 90. Flint only emits 0 or 90; 45 is the missing middle.
  5. 5Type joins the app — via a shared theme object. One file (defaults/chart_theme.yaml) set as properties.theme on all three EChart sites carries what Flint leaves unset: textStyle (undefined today), axisLabel.fontSize 10 → 12, axis chrome, tooltip and legend text. A theme merges under the option, so it can carry type — never the palette.
  6. 6Pie slices cap at 6 + Other. The corpus's worst failure is two client pies with ~20 slices each, leader labels overlapping into an unreadable mat.
  7. 7The chat panel gets this for free — it shares buildFlintOption and the theme object (which also reaches the expand modal, a surface compileReport never touches), and its 420px panel benefits most from the rotation and legend fixes. Its layout is not touched. One accepted consequence: chat parts persist their compiled option, so old chat snapshots keep the palette of their day.
  8. 8Rejected: dual y-axes, which 3 corpus charts use. It is the named #1 chart mistake; CHART_TYPES cannot express it and must not learn to.
