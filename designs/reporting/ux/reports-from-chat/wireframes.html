When a chat has produced reports, say so — and link to them.

A saved report already remembers the chat it came from: the report document carries a conversation_id. Today nothing reads it back, so a chat gives no sign that it ever produced anything durable. This deck sketches three places that signal could live — the same underlying question ("which reports point at this conversation?") presented three ways. Pick where it belongs; the plumbing is shared.

What we have

Every report saved from the chat page stores conversation_id. The link is one-directional: report → chat. A chat holds no list of its reports.

report.conversation_id = this chat's id

What's missing

Nothing queries that link from the chat side. So from a conversation you can't tell whether it produced one report, five, or none — or jump to them.

"Did I ever save this? Where did it go?"

The one new query

All three options run the same read: reports where conversation_id = this chat, owned by me, not deleted. A count for the rail, a short list for the panel.

Option A Rail signal — the count is cheap, the pill is not block-gated

A count on the conversation row — two ways to draw it

Getting the number is easy (see Compare). Drawing it is the catch: the rail is the external AgentConversations block, and its row schema is key / label / group only — no slot for a badge. So the styled, separately-clickable pill (A1) needs upstream block work, while a count folded into the row's label text (A2) ships with no block change at all. Same data, two very different costs.

Option B Panel section — in context, with titles & links new

"Saved from this chat", pinned in Results

The results panel is already "what this chat produced". A section at its top lists the saved reports from this conversation — title, when, visibility — each a row that opens the report. It answers the richer question ("which reports, take me there") for the chat you're actually in, and sits exactly where a just-saved report would appear.

Option C Inline marker — provenance in the transcript new

A marker where the report was cut, and a pin to find them

When a report is saved, a marker drops into the transcript at that point — so the record of when, in the exploration, each report came from is preserved in place. A small pinned banner at the top of the thread summarises them and jumps down. This is the richest signal and the most work; it reads as history, not just a link.

Compare what each option answers, and what it really costs

The cost reversal: B leads, A ships degraded

Once you account for the rail being an external block, the earlier ranking flips. The data is identical and cheap for all three — one read of "reports where conversation_id = this chat". What differs is the render: the panel (B) and the transcript (C) are drawn with our own Lowdefy blocks, so they carry no blocker; the rail (A) can only show a real pill by forking AgentConversations. So B becomes the lead, A ships in its label-text form (A2) now, and A1's pill and C stay optional later.
